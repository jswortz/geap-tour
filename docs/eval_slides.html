Define "good" · Metric Registry

Pick a metric, or write your own

Define a metric once and reuse it across offline runs and online monitors. There are three kinds, plus the split between reference-based and reference-free.

  • Predefined rubric: single-turn (Final Response Quality, Hallucination, Tool Use, Safety) and multi-turn (Task Success, Tool Use, Trajectory). Adaptive rubrics write their own criteria; static ones score 0 to 1.
  • Custom LLM-as-judge (types.LLMMetric), like GEAP Policy Compliance.
  • Custom code (types.CodeExecutionMetric): a deterministic def evaluate(instance) -> float.
  • Reference-based Exact Match vs reference-free rubrics.

Generate traces

Three ways to exercise the agent

A trace is the record of one run: the model inputs, the responses, and the tool calls. Produce them whichever way fits the stage.

  • Batch / test-case: run inference over a fixed suite for regression testing in CI.
  • Simulated: generate multi-turn scenarios and let an LLM play the user, grounded by environment_context. Inject mocked tools or 503s to test resilience.
  • Offline: score traces and sessions you already recorded in Cloud Trace and BigQuery, with no new inference.

☁ Google CloudPhase 3 · Scoring in production5 / 7
Continuous eval & guardrails

Watch quality in production

Online Monitors score live traffic as it comes in and send the scores to Cloud Monitoring, so you catch quality drift before users do.

  • Online Monitors: a roughly 10-minute loop that queries traffic, evaluates it, and reports. Sampling is configurable, and results land in Logging and Monitoring.
  • Metrics Explorer and dashboards: every score becomes a Cloud Monitoring metric (agent_eval/*, online_evaluator/scores), so you can chart it, compare it, and share it.
  • Quality-drift alerts: a per-monitor policy, the dashboard's Recommended Alerts, or gcloud / monitoring_v3.

The Quality Flywheel in one view

From "seems to work" to measured & monitored

  • Design: a reusable Metric Registry with predefined rubrics, custom LLM-as-judge, custom code, and reference-based Exact Match.
  • Execution: generate traces three ways, batch in CI, simulated (with user and environment simulation), and offline over historical traces.
  • Scoring: Online Monitors export every score as a Cloud Monitoring metric, visible in Metrics Explorer, dashboards, and drift alerts.
  • Refinement: optimize the agent's instructions with GEPA, SimplePromptOptimizer, or agents-cli, then re-evaluate. Repeat.

Built clean: current Google clients from PyPI, no monkey-patching, and 161 passing tests.
